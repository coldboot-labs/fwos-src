# fwos-src

Rust sources for first-party appliance programs. Not OCI recipes.

Bootstrap creates the first administrator in durable FWOS-local Identity configuration, separate from network Desired state. The Appliance console and HTTPS UI share credential verification and a source-qualified authorization boundary; v1 implements local accounts only. HTTPS sessions are held in memory: logout revokes them, and a UI restart or appliance reboot invalidates them.

`fwos-fwd-setup` is the Network startup program: it creates `fwd` and `mgmt`, prepares their fixed links and the Host netns connection, and moves Traffic NICs into `fwd` before netd starts. It then exits; netd owns ongoing network policy and does not enter the Host or Management netns.

`fwos` is the Appliance console Host program on VGA and serial: it offers the Bootstrap console before ownership, then an authenticated v1 recovery menu for status, restoration of the previous Accepted network revision, and explicit reboot. Network restoration goes through `netd`'s normal apply and recovery transaction; it does not restore older administrator credentials or roll back the Host image. Legacy full-CLI adapters remain callable for existing clients until their scheduled retirement, but are not advertised in the v1 menu. `fwos-update` is the Host update program: it wraps `bootc` in the Host netns and listens on a unix socket on `/var`; staging does not reboot. After an explicit reboot it checks appliance health (default target, fwd/mgmt, netd) and rolls back the bootc deployment if the new Release is not a working appliance. Manual Host-image `rollback` remains distinct from network restoration. `netd` is the built-in addon binary (OCI recipe in `fwos-builtin-addons`). `fwos-ui` is the UI built-in addon binary: HTTPS JSON plus a static JS SPA, unix-socket client of `netd` (not of the Host update program). The host image copies binaries at image-build; this tree is not vendored into `fwos-image`.
