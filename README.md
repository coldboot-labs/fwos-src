# fwos-src

Rust sources for first-party appliance programs. Not OCI recipes.

Bootstrap creates the first administrator in durable FWOS-local Identity configuration, separate from network Desired state. The Appliance console and HTTPS UI share credential verification and a source-qualified authorization boundary; v1 implements local accounts only. HTTPS sessions are held in memory: logout revokes them, and a UI restart or appliance reboot invalidates them.

`fwos-fwd-setup` is the Network startup program: it creates `fwd` and `mgmt`, prepares their fixed links and the Host netns connection, and moves Traffic NICs into `fwd` before netd starts. It then exits; netd owns ongoing network policy and does not enter the Host or Management netns.

`fwos` is the Appliance console Host program on VGA and serial: it offers the Bootstrap console before ownership, then an authenticated v1 recovery menu for status, restoration of the previous Accepted network revision, and explicit reboot. Network restoration goes through `netd`'s normal apply and recovery transaction; it does not restore older administrator credentials or roll back the Host image. Legacy full-CLI adapters remain callable for existing clients until their scheduled retirement, but are not advertised in the v1 menu. `fwos-update` is the Host update program: it wraps `bootc` in the Host netns and listens on a unix socket on `/var`. It refuses Host update and reboot until Bootstrap completion is durably recorded. The UI's `start_stage` pulls and stages in the background while `status` reports the booted, staged, and rollback deployments, the reboot requirement, and a running or failed staging operation; the legacy synchronous `stage` remains for existing clients. Staging does not reboot or touch networking, and a registry or download failure leaves no post-update health record, so it is never treated as a failed boot. Staging asks netd to preserve the Accepted network revision (refreshed at the explicit reboot) and records the previous and staged deployments. After the reboot, the new Release is accepted only when the default target is reached, `fwd` and `mgmt` exist, netd reports that it restored Accepted Desired state and the LAN services it requires, and the UI service is running; a running netd alone is not enough, and upstream reachability is not checked, so an unplugged WAN or ISP outage never causes a rollback. Otherwise it rolls back the bootc deployment and reboots without operator acknowledgement. Before netd starts, the previous Release recognizes the return from the update (`fwos-update restore-check`) and netd restores the preserved revision, as a new Accepted revision if the failed Release changed it. Identity configuration is not Desired state and stays current. `status` reports the last post-update health outcome. Host update health is separate from Apply confirmation. Manual Host-image `rollback` remains distinct from network restoration. `netd` is the built-in addon binary (OCI recipe in `fwos-builtin-addons`). `fwos-ui` is the UI built-in addon binary: HTTPS JSON plus a static JS SPA, unix-socket client of `netd` for network operations and of the Host update program for authenticated Host update status, staging, and explicit reboot. The host image copies binaries at image-build; this tree is not vendored into `fwos-image`.
